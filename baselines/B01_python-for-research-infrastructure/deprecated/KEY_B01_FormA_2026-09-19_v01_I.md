# KEY — Baseline B01, Form A (private; the instrument is public in `gozonerd/edu-python-for-poets---and-model-evaluators`)

**Do not copy into the public repo.** A baseline that is re-administered needs its key out of the
learner's path. Scoring is **0 · 1 · 2** per item: 0 not evidenced or skipped · 1 partly (the
indicator set is roughly half present, or right with a load-bearing term wrong) · 2 evidenced.
Score against the specimen `specimens/audit_against_ssots.py`, never against the grader's agreement
with itself. Where an answer is correct by a different route, it scores; indicators are not scripts.

## Band A (of 14)

**A1 (2):** `urllib` and `json` are standard library, shipped with Python, nothing to install;
`request` and `error` are two submodules being imported by name. With `requests`, a researcher would
need a dependency step (install, pin a version), and the tool would no longer run on a bare Python.
*1:* knows they are "built in" but cannot say what changes with a third-party library.

**A2 (2):** the `__name__` line runs `main()` only when the file is executed as a program, not when
imported by another file (so its functions can be reused). `action="append"` lets the flag be given
several times, collecting a list, so any number of SSOT files can be passed in order. *1:* one of the
two.

**A3 (2):** a tuple of two values, unpacked into two names by position; returning only `contents`
would make `system, contents =` fail (unpacking one thing into two names) or, if the caller were
changed, drop the system instruction from the request body. *1:* "two things come back" without the
unpacking or the consequence.

**A4 (2):** `resp` is a dictionary; `candidates` is a list of dictionaries; each has `content`, a
dictionary, whose `parts` is a list of dictionaries with a `text` key. `.get(key, default)` returns
the default when a key is missing instead of raising, so a response with no candidates yields an empty
string rather than a crash. *1:* shape right, `.get` reason missing, or vice versa.

**A5 (2):** goes around again on a retryable HTTP code (429/500/502/503/504) or a network error while
tries remain, after sleeping; stops early on success (`return`), on a quota 429 (`raise Quota`), on a
non-retryable code (`raise RuntimeError`), or when the last try fails (the `raise` inside the branch
re-raises). The final `raise RuntimeError("unreachable")` documents that every path out of the loop
already returned or raised, so reaching it means a logic error. *1:* the loop's behaviour right, the
final raise unexplained.

**A6 (2):** the file suffix, compared against `IMAGE_SUFFIXES`, picks the branch. JSON carries text,
not raw bytes, so image bytes are base64-encoded into text with a MIME type the model can decode.
`errors="replace"` keeps a file with a stray non-UTF-8 byte from crashing the run, substituting a
placeholder character. *1:* two of three.

**A7 (2):** `raw_response.json` (and `request_manifest.json`) are already written, because
`part_5_then` saves before parsing. Open `raw_response.json` first: if the candidate's `finishReason`
is `MAX_TOKENS`, the output cap (a setting in `part_4_how`) cut the JSON off, so the cause is a setting,
not the model and not the harness logic; if the text is complete but malformed, it is the model's
output. *1:* names the raw file but jumps to blaming the model or the parser without a way to tell.

## Band B (of 18)

**B1 (2):** from the shell's environment, put there by sourcing the secrets file (`set -a; . <path>;
set +a`) before running. A literal in the file would be committed, copied, pasted and read by other
models everywhere the file goes. `--key-var` switches which environment variable is read (a second
key, a different provider) with no edit. *1:* two of three.

**B2 (2):** an exception carries type, unwinds to whoever is prepared to handle it, and cannot be
silently ignored the way a `None` return can; a custom class lets the caller catch quota specifically
and route it (step down the ladder) while other failures keep their own paths. An HTTP 500 is
retried with backoff up to `tries`, then raised as `RuntimeError` (not caught by `main`, so the run
stops). *1:* the routing idea without the contrast, or the contrast without the idea.

**B3 (2):** waits 5, 10, 20 seconds. The cap keeps exponential growth from turning into minutes of
dead time per call. The property is idempotence: repeating the request must not change the outcome
or double-charge an effect (a read or a stateless generation is safe; a "create" or "send" may not
be). *1:* numbers right, idempotence missing or described as "it was a GET".

**B4 (2):** if parsing fails (truncated or malformed JSON), the evidence of what the model actually
returned and what was sent is already on disk; reversed, a parse failure would leave nothing, so the
failure could not be diagnosed and the call would have to be paid for again. *1:* "so you don't lose
the response" without naming what diagnosis needs.

**B5 (2):** records: run time (UTC), generator name, key variable name, model ladder, model used,
artifact name/bytes/sha256, each SSOT's name/bytes/sha256, request size in bytes, generation config,
token usage. A good addition (any one): the exact system prompt text or its hash, the provider's
response id, the API version, the specimen tool's own git commit, the finish reason. *1:* lists the
fields, addition is vague ("more logging").

**B6 (2):** concurrency buys wall-clock time when the bottleneck is latency; here the bottleneck was a
daily per-model quota, so four workers spent the day's 20 requests in seconds, all rejected, and got
nothing; the fact that decided it is that the limit was per day per model, not per minute, so pacing
plus stepping across models was the only design that could finish. *1:* buys/costs right, the
deciding fact missing.

**B7 (2):** the shell reported the id of a wrapper subshell it forked for the compound command
(`cd … && nohup python3 … &`); killing that left the Python child alive and reparented. Find the real
process by its own command line (for example `pgrep -f 'python3 audit_against_ssots'`) or by reading
its environment, not by the shell's `$!`. *1:* "there was a child process" without how to find it.

**B8 (2):** a package definition (`pyproject.toml` with a name, version, dependencies) and a declared
console entry point mapping a command name to a function, plus the code laid out as an importable
package. It matters because researchers iterate from wherever they are; a tool that must be run from
one folder with a path becomes a workflow tax and stops being used. *1:* names `pip`/`setup` vaguely
without the entry point, or the reason.

**B9 (2):** temperature 0 pins a sampling choice; the model id pins the model under test (a
scaffolding/prompting context choice at the provider level); the sha256 of inputs pins the prompt and
files, the prompting choice. Could still differ: the provider's model behind the same id (silent
updates), nondeterminism on the provider's side even at temperature 0, the system prompt if it is not
hashed, time-dependent content. *1:* two of the three mapped, or the residual variance missing.
